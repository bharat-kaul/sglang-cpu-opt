## Seven Areas

1. **Oracle Selection: AGREE, with adapter obligations.** Indexer and top-k now cite real published operations; top-k membership is explicitly order-independent although published `topk` uses default sorted order. [Local pool math](../../intel_cpu_models/dsa_compressor_cpu.py#L19) matches the published FP32 weighted softmax stage, not the full compressor: apply APE exactly once and transform the previous/current channel halves before pooling. Combine authority is multiply, sum, then cast, not bit-exact einsum. Sparse serving authority is the BF16 primitive for both candidate paths: FP32 score/output accumulators, BF16 cast of blockwise **unnormalized exponentials** before value GEMM, sink in the denominator, BF16 output. The inline FP32 reference remains diagnostic. Conformance of adapters to the pinned runtime remains unverified.

2. **Metrics: REVISE (clarification).** `max_rel_error` now names `max(abs(ref_i), abs_floor)`, but neither a positive `abs_floor` nor its relationship to the absolute allowance/near-zero switch is specified. Define `e_i = abs(candidate_i-ref_i)` and one explicit predicate: an absolute AND relative cap, a piecewise near-zero absolute rule, and `e_i <= atol + rtol*abs(ref_i)` are different policies. Do not silently choose among them. State per-row/per-output reductions and evaluate pre/post/comb separately. For either zero-norm vector, use the declared absolute-only branch and record cosine as not applicable, rather than evaluating NaN then invoking the blanket nonfinite-metric failure. For masked logits, validate the reference-owned mask/sentinels separately and compute diagnostics only over the declared finite domain; define all-masked rows as not applicable. Identical legal `-inf` values must not create a numerical failure through subtraction. These explicit exceptions should outrank generic metric-completeness wording; unexpected nonfinite evaluated metrics must still fail.

3. **Ties / Selection / Masks: REVISE (clarification), core corrections AGREE.** Reference cutoff and gathered reference scores plus exactly k distinct in-range raw indices resolve the duplicate-index defect. Specify whether the selected-score multiset is an additional gate or only an alternative implementation of the band rule, and its comparison tolerance. At a `-inf` cutoff, explicitly include all finite valid scores and fill the remaining raw slots from legal masked positions, without subtracting infinities. Verify the actual caller transformation: valid post-mask IDs remain unique and correctly offset; repeated `-1` is legal, with `k-min(k, valid_count)` sentinels when valid scores are finite. Checking only distinctness after masking would be wrong. Preserve the stated k=0 empty-int64 exception, k=S and invalid-k checks, and int32 caller conversion. Tie substitutions across different KV identities remain a semantic user decision; the required composed sparse-consumer check is essential, not implied by set equality.

4. **Bit-Exact Classification: AGREE.** D3's three claims are properly separated. Freeze the path and record actual thread counts/dispatch when eventually testing them. Define bit identity versus numerical equality, including signed zero, for any ratified exactness requirement. No scalar-FP32 or repeatability label establishes oracle equality.

5. **Fail-Closed Layer 0 and Precedence: AGREE on intent; REVISE the applicability contract.** Legal padding/mask `-inf` is recognized; all-masked pool reachability/exclusion must be established rather than blessing zero. Missing oracle/case, exception, unratified policy and child failures cannot produce full PASS; layer-0-only is PARTIAL. Real benchmark plus exact wrapper failure injection is correctly required, including pipes/final commands, but has not been executed here. The per-indexer rule clearly intends selection gating with logit error diagnostic, yet global layer-1/"ANY failure" wording has no explicit applicability matrix. State that continuous ops use layer 1, top-k uses layer 2, indexer uses layer 2 with finite logit-error diagnostics non-gating unless the user opts in, and layer 0 always applies. Expected not-applicable metrics must differ from missing/failed evaluations. BF16-versus-global-cosine precedence is explicitly still a USER decision, not already resolved.

6. **Shape Coverage: FLAG, intent AGREE.** Pinned config gives attention H=64/D=512, index D=128, top-k=512, window=128 and ratios 0/4/128. Published overlap makes ratio 4 an 8-token pool, so the three pool shapes are justified as stage contracts. At context 4096, sparse allocated index widths are 128, `128+min(512,4096/4)=640`, and `128+4096/128=160`; early causal rows have fewer valid entries. These are not universal lengths or captured tensors. A machine-enumerated manifest must bind phase, batch, TP-local heads, strides/dtypes, mask/state, offsets/gather, cadence/remainders and ring wrap to source and eventual capture identities. The policy appropriately retains runtime-captured manifestations and authoritative full-model all-layer parity; this review satisfies neither gate.

7. **Numerical Choices: FLAG / USER.** No thresholds or exactness paths are ratified here. The by-key list is an improvement, but still needs explicit keys/mapping for `abs_floor`/near-zero switching, selected-multiset tolerance, selection-only versus additional-logit gating, and `topk_set_match` (currently only in the proposed layer-2 object). Distinguish diagnostic relative-error reporting from the actual acceptance predicate. Missing calibration or undecided values are not grounds for FAIL; unresolved choices must not become implicit defaults or a full implementation PASS.

## E1-E3 Revisited

**E1 (equation replay).** Set hc=4, iterations=20, eps=1e-6, scales `[1,1,1]`, bases zero, first eight mixes zero and the final sixteen mixes to:

```text
  0   0 -20 -20
-20   0 -20 -20
-20 -20   0 -20
-20 -20 -20   0
```

Replayed the published recurrence using Perl v5.40.2, `OMP_NUM_THREADS=1`, both binary64 and explicit `unpack('f',pack('f',value))` rounding after arithmetic/exp and sequential sums. Binary64 row sums: `[1.02435114667548, 0.975641033557138, 1.00000190926002, 1.00000190926002]`. Rounded-binary32 row sums: `[1.02435111999512, 0.975641012191772, 1.00000190734863, 1.00000190734863]`; maximum row residual `0.0243589878082275`. Binary32 pre is `0.500001013278961` per entry; post is 1. This supports removal of the old `1e-5` convergence invariant, not a new acceptance bound. V2 instead compares all three outputs to the conformed recurrence; convergence residual alone is diagnostic.

**E2 (rounded-FP32 replay).** For `a=16777216, b=1, c=-16777216`, `(a+b)+c=0`, while `a+(b+c)=1`. Both fixed trees are deterministic. V2 respects that distinction; no particular Torch/backend reduction tree is asserted.

**E3 (math and mask replay).** `[2,2,1]`, k=2: `[0,0]` gathers `[2,2]` but violates v2's raw uniqueness guard; `[0,1]` does not. `[1,1-5e-7]`, k=1: the measured binary64 gap is `4.99999999958867e-7`, inside the proposed `1e-6` band, but exact selected-score equality would reject the lower entry. V2 does not mandate exact multiset equality, so this is a clarification requirement, not a demonstrated wrong verdict. For `[2,-inf,-inf]`, k=3, distinct raw IDs map to `[offset,-1,-1]` with one valid position; repeated sentinels must remain legal. With `[-inf,-inf]`, k=2, the cutoff itself is `-inf`; subtraction-based comparison is undefined and the declared sentinel branch must apply. Identical zero vectors similarly require the declared cosine exception. These expose ambiguous implementations, not failures of a nonexistent evaluator.
