Reviewer: GitHub Copilot. Date: 2026-10-09. Reviewed HEAD: `19ea82a4bbb9059ea70873fb1610f6d8ed8bc533`.
Scope: F4 design only; not round-5 parser/reconciliation, implementation acceptance, or tolerance ratification.
Reviewed [policy](../results/acceptance_policy.json), SHA-256 `6eecd117113add6b3e6d22025dc1d465a83c67e674953cffc59505c0a9d057da`.

## Severity Findings

- **High / F4-D1: nonexistent authoritative indexer oracle.** [Policy oracle](../results/acceptance_policy.json#L47) names a BF16 indexer primitive in the published kernel module. Its complete function inventory has no indexer primitive. Scoring is in published `Indexer.forward`, including BF16 einsum, BF16 ReLU-times-weights and BF16 reduction-result boundaries, then TP reduction and masking. A BF16 GEMM alone or FP32 epilogue is not that oracle. Replace the citation with the exact published stage and an explicitly specified adapter; retain FP32 replay only as a diagnostic. This is an objectively wrong oracle, not a threshold choice.
- **High / F4-D2: the proposed Sinkhorn invariant rejects the reference.** [Row/column bound](../results/acceptance_policy.json#L32) and [per-op constraint](../results/acceptance_policy.json#L71) demand near-double-stochasticity that the published finite-iteration algorithm does not guarantee. Counterexample E1 below exceeds `1e-5` by over 2,400 times. Compare the actual epsilon-regularized recurrence; report convergence residuals separately, or explicitly restrict the input domain with evidence. Do not silently increase the bound to fit this example.
- **Medium / F4-D3: determinism does not imply oracle bit-exactness.** [Classification](../results/acceptance_policy.json#L12) conflates two independent claims. E2 gives deterministic FP32 reductions with different answers. Exactness may be a user-selected requirement for a named runtime/path, but is not entailed by scalar FP32 or thread determinism. Global `true`, per-op "preferred; else", and sparse "tight" also need one unambiguous precedence rule.
- **Medium / F4-D4: selection, metrics and enforcement remain underspecified.** The tie multiset lacks score ownership, comparison tolerance, uniqueness and sentinel rules; relative error lacks a denominator/zero rule; global numerical gating conflicts with indexer selection-only gating. These are design ambiguities requiring clarification, not claims that an existing validator accepts the counterexamples.

## Seven Requested Areas

1. **Oracle Selection: REVISE.** Authority follows the published operation, not the CPU backend. Indexer: use published model lines 420-432, including rounding and caller mask/offset semantics. Top-k: `torch.topk` is suitable for the selection fragment, with tie-independent membership checks; the published call uses default sorted order, whereas the proposal uses `sorted=False`, so state the order-independent scope explicitly. Pool: [local reference](../../intel_cpu_models/dsa_compressor_cpu.py#L19) matches FP32 softmax-weighted pooling after correctly preparing overlap/APE inputs, not the complete compressor (state, cast, norm, rotation, quantization). Combine: published `hc_pre` uses multiply then `torch.sum`, followed by a dtype cast; local einsum is mathematically equivalent, not an established bit-exact oracle. Sinkhorn: pin and independently conform the proposed SGLang helper to the published epsilon placements, iteration count, pre/post transforms; its import name alone is not authority. Sparse: use the published BF16 primitive for serving equivalence on both candidate paths, plus [inline FP32 reference](../bench_sparse_attend.py#L19) for scalar-math diagnostics. That reference includes the sink but is pre-gathered and lacks the published BF16 cast of blockwise **unnormalized exponentials** before the value GEMM and final BF16 output. A CPU replay is a proxy until conformed against the published runtime. Do not use the stale no-sink oracle.

2. **Metric Adequacy: REVISE.** Agree that cosine alone is insufficient. Specify per-row/per-output maximum errors, reference denominator, absolute-error allowance near zero, zero-vector cosine behavior, and explicit rejection of nonfinite *metrics*. For identical zero outputs, ordinary cosine is undefined (epsilon-stabilized variants return zero), so a universal positive cosine floor can reject exact results. Avoid flattening away a failing row or mixing pre/post/comb. Recommend a user-ratified absolute-plus-relative comparison alongside cosine, not an unspecified `max_relerr`. Selection is a necessary indexer check; whether logits are diagnostic-only or an additional gate is a user decision. Resolve the contradiction with layer 1 and "ANY failure". Published BF16 logits differing from a tiled FP32 epilogue is not evidence that the reference is wrong. `511/512` is a mismatch under proposed set-match 1.0 unless the differing identities actually satisfy the approved tie rule. Sinkhorn needs numerical checks on all three outputs and the true recurrence, not a universal row-sum-to-one constraint (E1).

3. **Ties / Selection / Masks: REVISE.** Derive the cutoff and gathered scores from the **reference**, never candidate logits. For a finite cutoff, require exactly k distinct in-range raw indices, include every score above cutoff plus the approved band, exclude every score below cutoff minus the band, and fill the remaining slots only from the band. State the selected-multiset comparison tolerance explicitly (E3); band width and permissibility of substituting different KV identities are user decisions, not automatic semantic equivalence. For k=0, validate empty `[N,0]` int64 and skip cutoff/cosine reductions. Handle k=S, duplicate scores, and invalid k explicitly. Published prefill adds `-inf`, chooses `min(512,end_pos//ratio)`, then converts causally invalid choices to `-1` and adds the offset only to valid choices; decode adds the offset directly. Separate raw distinct indices from post-mask output, where repeated `-1` is legal. Check valid membership and sentinel counts; do not compute `abs(-inf - -inf)` for ties. Exercise zero/fewer-than-k valid positions and distinguish fragment int64 from the caller's int32 conversion. Set equivalence does not establish ordered sparse-kernel numerical equivalence: reordering can change 64-entry block boundaries and BF16 accumulation, so test the composed consumer too.

4. **Bit-Exact Classification: REVISE.** Require separate recorded claims for repeated-run reproducibility, same-path equality across actual thread counts, and equality to a pinned oracle. E2 disproves their implication. Pool online reductions, combine FMA/reduction order, Sinkhorn transcendental implementations, and sparse reductions need not share Torch/GPU bits. User can require exact equality for a specifically frozen path, or ratify a tolerance; do not blanket-certify scalar paths as exact. Numerical equality with relative error zero is also not necessarily bit identity (signed zero). Specify which is meant and record compiler/runtime/backend identity.

5. **Fail-Closed Layer 0: AGREE WITH REVISIONS.** Splitting structural checks and exit propagation from user tolerances is sensible, but the proposal explicitly says NOT YET ENFORCED, so it does not demonstrate either exit today. Require a complete expected op/path/case inventory; missing oracle, malformed/unratified policy, skipped case, exception, NaN metric, or missing result must not yield full F4 PASS. A layer-0-only run must be labeled partial. Make finiteness stage/domain-specific: valid compressor padding scores and masked indexer logits include `-inf`; finite outputs are appropriate on documented supported domains. All-masked pool softmax is NaN in Torch while a zero-returning implementation differs; establish reachability/exclusion instead of blessing zero or rejecting legal leading padding. Reject NaN/+inf data and invalid indices/scalars where outside the contract; validate actual dtype/device/layout/scalar support, not merely assume F9 covers it. Verify thread counts and dispatch actually exercised. Test deliberate failures through the real benchmark and exact job wrapper (including piped logging, child failures and final shell commands), without submitting a cluster job. Nonzero child exit does not automatically imply nonzero shell/job exit.

6. **Shape Coverage: FLAG.** Agree the draft explicitly names all pool contracts `(128,512)`, `(8,512)`, `(8,128)` and sparse union lengths `128/640/160`; this fixes omission in intent only. Require a machine-enumerated case manifest with source/capture identity, dimensions, strides/dtypes, backend, phase, batch, TP and mask/state metadata. At context 4096, lengths derive as window 128 alone, `128+min(512,4096/4)=640`, and `128+4096/128=160`; they are not universal context-independent lengths. Test prefill/decode, first overlap with leading `-inf`, cadence boundaries/remainders, causal masks, ring-buffer wrap, offsets, gather, and multiple batches/contexts. Ratio 4 creates an 8-token pool, not an independent compression ratio 8. Exercise H=64/D=512 sparse and TP-local variants. Random normal/heavy-tail and FP4-grid cases are useful **synthetic proxies**; eventual runtime-captured real-forward tensors and authoritative full-model all-layer parity remain required. Neither K=512 pre-gathered nor this review meets those gates.

7. **Proposed Numbers: FLAG, USER DECISIONS.** Do not ratify `cos>=0.999999`, FP32 `rel<=1e-4`, BF16 `rel<=1e-2`, `tie_eps=1e-6`, or exact selection here. Their suitability depends on the defined metric, near-zero/cancellation behavior, scale, reduction length, input domain and per-op/backend scope. A BF16 tolerance does not override the global cosine floor unless precedence says so. `1e-5` cannot be a universal Sinkhorn convergence guarantee (E1), regardless of tolerance preferences; preserve algorithm epsilon `1e-6` separately from acceptance tolerances. Needed decisions include absolute-error/zero handling, tie-band score scale, exact-vs-near ties, selection-only-vs-additional-logit gating, and any allowed non-tie selection loss. The "6 tolerance knobs" wording does not enumerate a coherent set: the current objects contain five layer-1 fields and three layer-2 fields, including a boolean and a rule string. Enumerate ratifiable decisions by key. Historical `.045/.092` logit and sparse `.0025` errors are supplied context, not independently rerun or sufficient calibration data in this review.

## Counterexamples and Method

**E1: published Sinkhorn is not a convergence certificate.** Set hc=4, iterations=20, eps=1e-6, scale `[1,1,1]`, base zero, first eight mixes zero, and final sixteen mixes to this finite matrix:

```text
  0   0 -20 -20
-20   0 -20 -20
-20 -20   0 -20
-20 -20 -20   0
```

Replay published kernel lines 401-423: row-softmax plus eps; one column division by sum+eps; nineteen row/column divisions by sum+eps. In-memory AWK double replay produced row sums `[1.02435114667548, 0.975641033557138, 1.00000190926002, 1.00000190926002]`. Independent Perl replay using `unpack("f",pack("f",value))` after each arithmetic operation produced `[1.02435111370067, 0.975641042044117, 1.00000191422812, 1.00000191422308]`; column sums were `[0.999998927267370, 0.999999047038486, 0.999999004942538, 0.999999004947597]`. These are equation replays, not executions of TileLang/GPU or the candidate kernel. The large residual is finite-iteration convergence, not a floating-point edge or an assertion of checkpoint reachability. The proposed unrestricted normal/heavy-tail domain supplies no restriction excluding it.

**E2: deterministic FP32 does not imply bit-exact oracle parity.** With exact FP32 inputs `a=16777216`, `b=1`, `c=-16777216`, explicitly rounded `(a+b)+c=0`, whereas `a+(b+c)=1`. Both are repeatable with any thread count if their reduction tree stays fixed. Executed with Perl float32 pack/unpack; not a claim that any particular Torch invocation uses either tree.

**E3: tie multiset ambiguities (mathematical, not an existing-validator test).** Scores `[2,2,1]`, k=2: bad raw indices `[0,0]` have selected score multiset `[2,2]`, identical to valid `[0,1]`; the boundary exemption needs a separate uniqueness guard. Scores `[1,1-5e-7]`, k=1, tie_eps=1e-6: both indices lie in the proposed band, but exact selected-multiset equality rejects the lower score. Scores `[-inf,-inf]` make subtraction-based tie tests NaN. These examples require an explicit rule, not assumed validator behavior. Even exact tied scores can refer to different KV values; tie acceptance is not a proof of identical downstream attention.
